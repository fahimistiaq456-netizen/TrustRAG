# Graph-Based Retrieval

## What it does
Adds an optional, local-only knowledge-graph retrieval layer that can surface facts
wedged *across* multiple chunks/docs, which dense retrieval may miss. When enabled, graph
retrieval runs in parallel with FAISS and its evidence is fused before reranking:

```
Question → query understanding
        → [ FAISS  |  Graph ]  → evidence fusion → rerank → NLI → answer
```

## Why it exists
Questions that need relationships between multiple pieces of evidence (for example
"Which eligibility conditions apply to international transfer applicants?") benefit from a
graph that records `Document → Section → Entity/Concept → Related Entity/Concept`. The
graph expands from query terms to neighbours and appends their provenance-preserving facts
to the FAISS evidence.

Graph retrieval is **optional** (`HALLUFIX_GRAPH_ENABLED=false` by default). When disabled
(or when no graph can be built/loaded), normal RAG returns the FAISS chunks unchanged —
behaviour is identical to the non-graph pipeline.

## Architecture
- `backend/graphstore.py`:
  - Builds a `networkx.Graph` from chunk dictionaries using simple deterministic
    entity (capitalized-word) and keyword extractors — no NER model, works offline on CPU.
  - Node kinds: `DOCUMENT` / `SECTION` / `ENTITY` / `CONCEPT`.
  - **Every node carries provenance** back to `document`, `page` and `chunk_id`; a graph
    fact is never generated without a traceable source.
  - `save` / `load` persist via `nx.node_link_data` JSON (`data/index/graph.json`).
- `backend/graph_retriever.py`:
  - `build_graph(chunks, path)` constructs + persists the graph (called on `/ingest`).
  - `graph_retrieve(question, faiss_chunks, ...)`:
    1. extract query entities/concepts (query understanding),
    2. find seed nodes,
    3. breadth-first expand neighbouring nodes (≤ `HALLUFIX_GRAPH_NEIGHBORS`),
    4. collect neighbour provenance and fuse into the FAISS chunks,
    5. attach graph-only facts as pseudo-chunks flagged `from_graph=True`.
- `backend/api.py::_run_rag` composes `retrieve → graph_retrieve → rerank_candidates`,
  reporting `graph_used` / `graph_neighbors` in the payload.

## Configuration (`backend/config.py`, `.env`)
| Variable | Default | Meaning |
|---|---|---|
| `HALLUFIX_GRAPH_ENABLED` | `false` | Enable graph retrieval |
| `HALLUFIX_GRAPH_NEIGHBORS` | `4` | Adjacent nodes expanded per seed |

## How to run / test
```bash
# Build the graph together with the index after ingesting sources
python -m backend.build_index data   # or upload via Sources tab

pytest tests/test_graph.py   # graph construction + provenance + fusion
```
Enable in `.env` with `HALLUFIX_GRAPH_ENABLED=true`.

## Limitations & testing
- Tests cover graph construction, provenance retention, seed finding and evidence fusion.
- The entity/concept extractor is a light heuristic (offline, deterministic); it is not a
  semantic ontology. For thesis claims treat the graph as an additive recall-booster
  whose actual benefit must be quantified by the multi-domain comparison.
- Graph facts are phrased from provenance, not generated by an LLM, so they never
  introduce unsourced content.
